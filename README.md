# Automated Credit Card Approval System

Predicts whether a credit card application should be **approved** or
**rejected**, based on the applicant's financial and demographic profile —
trained on four classification algorithms and served through a Flask web
app, with an optional IBM Watson Machine Learning cloud deployment path.

## How it works

```
application_record.csv  ┐
                         ├─► preprocessing.py ─► feature matrix (X) + binary target (y)
credit_record.csv        ┘         │
                                    ▼
                         train_models.py
              (Logistic Regression, Random Forest,
                   XGBoost, Decision Tree)
                                    │
                          picks best model by ROC AUC
                                    ▼
                     models/best_model.pkl + feature_encoder.pkl
                                    │
                                    ▼
                              app/app.py (Flask)
                         instant Approve / Reject UI
                                    │
                          (optional) deployment/ibm_watson_deploy.py
                            → cloud REST scoring endpoint
```

### Feature engineering — the key step

`credit_record.csv` stores a **multi-class** monthly payment `STATUS` code
per applicant (`0`–`5`, `C`, `X`). `src/preprocessing.py` collapses this
history into a single **binary** risk label per applicant:

- `STATUS` ever in `{2, 3, 4, 5}` (60+ days past due) → `TARGET = 1` (high
  risk → reject)
- otherwise → `TARGET = 0` (low risk → approve)

This is exactly the transformation described in the compliance-review
scenario: batch-screening applicants with past-due records by turning messy,
multi-class payment codes into a clean, actionable ineligibility flag.

## Getting started

```bash
pip install -r requirements.txt

# 1. Generate the dataset (or drop in the real application_record.csv /
#    credit_record.csv — same column names, no code changes needed)
python data/generate_data.py

# 2. Train all four models and save the best one
cd src && python train_models.py && cd ..

# 3. Run the web app
cd app && python app.py
# open http://localhost:5000
```

## Using real data instead of synthetic data

Drop your own `application_record.csv` and `credit_record.csv` (same
column names as generated by `data/generate_data.py`) into `data/`, then
re-run `train_models.py`. No other code changes are required.

## Models compared

| Model | Notes |
|---|---|
| Logistic Regression | Fast, interpretable baseline; `class_weight="balanced"` |
| Decision Tree | Depth-capped to limit overfitting |
| Random Forest | 300 trees, balanced class weights |
| XGBoost | Gradient-boosted trees; falls back to `GradientBoostingClassifier` automatically if `xgboost` isn't installed |

`train_models.py` evaluates all four on Accuracy, Precision, Recall, F1, and
ROC AUC, prints a comparison table, saves `models/model_comparison.csv` and
three plots (`roc_curves.png`, `confusion_matrix.png`,
`model_comparison.png`), and persists the ROC-AUC winner as
`models/best_model.pkl`.

## Web app

- `GET /` — application form (personal / income & employment / housing /
  contact-on-file).
- `POST /predict` — scores the form and renders an Approved/Rejected
  "stamp" with confidence and estimated default risk.
- `POST /api/predict` — same scoring logic as a JSON API, for batch tools or
  integration with other internal systems (e.g. the compliance team's
  batch-screening workflow).

## Cloud deployment (IBM Watson Machine Learning)

`deployment/ibm_watson_deploy.py` registers `best_model.pkl` with IBM Watson
Machine Learning and creates an online (real-time) deployment, so the same
model can be called as a managed, auto-scaling REST endpoint instead of (or
in addition to) the local Flask app. Set `WML_API_KEY`, `WML_URL`, and
`WML_SPACE_ID`, then run:

```bash
python deployment/ibm_watson_deploy.py
```

## Scenario coverage

- **Automated screening** — the analyst enters a profile in the web UI and
  gets an instant decision to prioritize manual review.
- **High-risk identification & compliance review** — the binary-target
  feature engineering step is exactly what flags applicants with a past-due
  history as ineligible; `/api/predict` supports batch screening.
- **Customer self-service eligibility check** — the same form doubles as a
  pre-application eligibility check for prospective customers.

## Notes on the dataset

No real dataset was provided, so `data/generate_data.py` synthesizes a
realistic ~8,000-applicant dataset structured like the standard
"Credit Card Approval Prediction" data (`application_record.csv` +
`credit_record.csv`), with risk correlated to income, employment stability,
education, and other applicant features so the trained models reflect
genuine, learnable credit-risk patterns rather than random noise. Replace
these two CSVs with real data at any time — the rest of the pipeline is
unchanged.
